# quiz_point — クイズ用リアルタイム得点表

クイズ大会・フリバ用の得点共有アプリです。ホストが部屋を作って招待リンク（または4桁の部屋コード）を配り、
参加者は各自のスマホから名前を入れて入室します。**全員が自分の得点を自分で操作**し、全員の得点・順位・チーム得点・推移グラフがリアルタイムに共有されます。

公開ページ: GitHub Pages（`docs/index.html`）。データは Firebase Realtime Database に保存します。

## 主な機能

- **部屋**：ホストが部屋を作成（ホストも1プレイヤーとして参加）→ 招待リンク / 部屋コードを共有。再読み込みしてもホストは自動で復帰
- **ルール**（ホストが選ぶ。参加者は「正答 / 誤答」を押すだけで得点・勝ち抜け・脱落・休みが自動で決まる）。計算の定義は [Tokuten](https://tokuten.baton8.com/) に合わせています
  - 正解数で勝負：**N〇M✕**（0 で制限なし＝〇✕カウント。誤答後の休み〈Tokuten の M〇N休〉・連答ボーナスも設定可）／**フリーズ**（k 回目の誤答で k 問休み）／**スウェーディッシュ**（誤答で付く✕は正解数 0→1・1〜2→2・3〜5→3・6〜9→4・10〜14→5…）
  - 総得点で勝負：**+M/−N**（正解 +M・誤答 −N）／**アップダウン**（正解 +1、誤答で 0 点）／**M by N**（〇側 ×✕側。初期値と増減を別々に設定。✕側 0 で脱落）／**ディバイド**（初期 10・正解 +10・n 回目の誤答で ÷n 切り捨て。毎回 ÷D〈分数で厳密〉も選べる）
  - 自由計算（下記）。新しい部屋は「〇✕カウント」で始まります
  - 勝ち抜けの点・脱落の✕などのしきい値は 0 で無効。ルールを変えると、全員の得点・状態と問題番号がリセットされます
- **勝ち抜け・脱落の宣言**：自動判定とは別に、各自が採点バーの「勝ち抜け」「脱落」を押して宣言できる（「元に戻す」で取り消し可）。並びは 勝ち抜けた順 → 競技中（同点なら先に正解した人が上）→ 脱落（後から脱落した人が上）
- **問題の進行と休み**：ホストが「次の問題 ▶」で Q 番号を進める（グラフの横軸にも使う）。休み中の人は自分の「問題を進める」でも休みを減らせる（ホストと両方押しても二重には減らない）
- **自由計算**：各自が画面下のバーで自分の得点を操作
  - 〇✕（規定点の加点・減点）／加点のみ／自由計算（＋ − × ÷、`2`・`0.5`・`1/2` のような小数・分数）／クイック（＋1〜＋5・−1）
  - 得点は内部で**有理数（分数）として厳密に保持**し、表示時だけ小数に丸める（`÷3` してから `×3` しても誤差なし）
- **元に戻す（Undo）**：自分の得点だけを1手戻す（他の人の操作には影響しない）
- **観戦モード**：採点バーの目のアイコンで「観戦」にするとランキングから外れて見るだけになる（司会向け）。ホストは他の人を観戦にしたり参加に戻したりできる
- **記録**：「記録」タブに、この部屋での〇✕の累計と勝ち抜け・脱落の回数。リセットやルール変更でも消えない
- **ホストの管理**：得点モード（＋/− 数値・〇/✖ Simple）、チーム得点の計算（和・積）、全員を 1 に／全員リセット、チームの作成・改名・削除、プレイヤーの改名・削除・観戦にする
- **チーム**：所属は各自が自分のバーからタップで選択。チーム得点はメンバーの和または積
- **グラフ**：得点の推移を折れ線で表示（横軸は問題番号。グラフタブを開いている間だけ推移データを受信）
- **見せ方**：1 人 1 行の詰めたランキング（スマホで 8 人前後）・自分の得点と順位を画面下に大きく・得点が変わると数字が弾む・順位の入れ替わりアニメ・1〜3位のメダル色・勝ち抜けたときのバナーとファンファーレ（効果音はヘッダーで ON/OFF）
- **使い方**：ホーム右上の ? と、部屋の「…」メニューから
- **ホストのキーボード操作（PC）**：→ で次の問題、← で 1 問戻す
- **表示の切替**：ヘッダー（とホーム右上）のボタンで 自動（OS に合わせる）→ 明るい → 暗い。選んだ表示は端末に保存
- **ホストの他人操作**：ランキングの行（観戦中の人はチップ）を押すと、名前を変える／チームを変える／観戦にする（参加に戻す）／削除 のメニュー
- **招待**：ヘッダーの部屋コードを押すと QR コードとリンク（参加者も開ける）
- **大画面モード**：`?room=部屋コード&view=board` で、操作 UI の無いプロジェクタ向け表示（ランキング・チーム得点・参加用 QR）。ホストの管理パネルから開ける。人数と画面の大きさに合わせて文字の大きさを選び、右上の「全画面」で全画面に。得点が動くと右の列に上位 5 人の推移グラフ
- **結果発表**：ホストが押すと全員の画面に表彰台と最終順位。CSV で保存もできる
- **ログ**：誰が何をしたか（〇✕・Undo・問題の進行・ホストの操作）を新しい順に最新50件
- **オンライン表示**：接続中の人の名前の横に緑の点
- **リーチ**：あと 1 問正答で勝ち抜けの人に「リーチ」の印（ランキング・大画面）。休み中は「休み あと n 問」（誤答したその問題では「次の n 問は休み」）
- **画面を消さない**：部屋にいる間はスマホの画面が暗くならない（対応端末のみ）
- **通信の知らせ**：つながらないときは上に小さく「接続中…」／「通信が切れています」、送るのに時間がかかるときは押したボタンに「送信中…」
- **うっかり対策**：部屋の中でブラウザの「戻る」を押すと退出するか確かめる。同じ名前の人がいる部屋に入るときは確かめる。ホストに削除された人には「もう一度入る」
- **自動再入室**：一度入った部屋は、再読み込みしても名前入力なしで戻れる（自分の名前は採点バーの鉛筆から変更）
- 部屋は作成から 24 時間で掃除対象になります

## 開発

```bash
npm install
npm run build   # docs/index.html を生成（JS・CSS を埋め込んだ1ファイル。外部 CDN は使わない）
npm test        # ビルドしてから、データ層テストと画面テスト（jsdom）を実行
npm run screenshot  # screenshots/ に主な画面のスクリーンショット（テスト用データ。Chrome が必要）
npm run audit       # UI の自動チェック：320〜1280px × 明るい/暗い で、はみ出し・文字のコントラスト（WCAG）・押せる大きさ・名前のないボタン・一画面に見える人数を測って点数を出す
```

`docs/index.html` をブラウザで直接開いても動きます（Firebase に接続します）。

### 構成

```
app/
  main.jsx               エントリーポイント
  App.jsx                画面の切り替え・入室・部屋作成

  data/
    store.js             データ層（部屋・プレイヤー・履歴・得点推移の読み書き）
    firebaseAdapter.js   Firebase Realtime Database への接続
    config.js            Firebase の接続設定
  lib/                   ルール（rules.js）・得点計算（有理数）・チーム得点・得点推移の展開・ID 生成・効果音
  ui/                    アイコン・共通部品（Card・Button など）
  components/            ランキング・チーム・グラフ・記録・採点バー・管理パネルなど

docs/index.html          ビルド成果物（GitHub Pages で配信）
```

### データ構造（Realtime Database）

| パス | 内容 |
|---|---|
| `rooms/{部屋}` | `hostToken`・`createdAt`・`rule`・`q`（問題番号）・`seq`（勝ち抜け・脱落順の通し番号）・`phase`（結果発表中）・`scoreMode`・`teamMode`・`players/{id}`（項目は `app/lib/rules.js` 冒頭。観戦中は `spectator`、記録は `rec`）・`teams/{id}` |
| `history/{部屋}/{プレイヤー}` | そのプレイヤーの得点変更前の値（プレイヤー別 Undo 用） |
| `timeline/{部屋}` | 得点推移のイベント（変わった人の分だけ） |
| `roomIndex/{部屋}` | 作成時刻（期限切れの部屋の掃除用） |
| `log/{部屋}` | 操作ログ |
| `presence/{部屋}/{プレイヤー}` | 接続中なら true（切断されると Firebase が消す） |

同時に操作しても更新が消えないよう、プレイヤー1人分の変更は `players/{id}` への transaction、全員分の変更は `players` への transaction で書き込みます。

Firebase のセキュリティルールで、上のパスへの読み書きを許可してください（`timeline`・`roomIndex`・`log`・`presence` が拒否されても得点操作は動きますが、それぞれグラフ・古い部屋の掃除・ログ・オンライン表示が働きません）。
